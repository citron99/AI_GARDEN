# Обработка фотографий и внешний AI

- Загруженные изображения проверяются, повторно кодируются и сохраняются без EXIF/GPS.
- В production очищенные оригиналы хранятся в приватном S3-совместимом bucket;
  доступ владельцу предоставляется короткой подписанной ссылкой, а lifecycle и
  резервное копирование настраиваются политиками выбранного хранилища.
- При `AI_PROVIDER=openai` внешнему AI-провайдеру передаётся уменьшенная JPEG-копия
  очищенной фотографии, описание симптомов, сведения о растении и регионе и ответы
  на уточняющие вопросы.
- В запросе Responses API устанавливается `store=False`. Это отключает хранение
  application state ответа, но не отменяет abuse-monitoring logs OpenAI, которые по
  стандартной политике могут храниться до 30 дней. Особые Zero Data Retention или
  Modified Abuse Monitoring controls требуют отдельного согласования с OpenAI.
- Вместо email передаётся стабильный HMAC `safety_identifier`, созданный из внутреннего
  ID пользователя и отдельного `AI_SAFETY_SECRET`.
- API-ключи и содержимое фотографий не записываются в журналы приложения. Сохраняются
  только технические метрики: request ID, модель, токены, задержка, примерная стоимость,
  успешность и безопасный тип ошибки.

Официальная политика OpenAI: https://developers.openai.com/api/docs/guides/your-data

## Погодный сервис

Для получения прогноза Open-Meteo получает название местоположения сада для геокодирования, а затем координаты найденного населённого пункта. Email, имя пользователя, фотографии, сведения о растениях и диагностические данные в погодный сервис не передаются. Прогноз кэшируется приложением на ограниченное время.

## Партнёрские предложения

Партнёрские товары всегда отделены от диагностики и помечены как реклама.
Приложение не отправляет партнёру симптомы, фотографии, ответы, email или имя
пользователя. Перед переходом сервер сохраняет только внутренние ID товара и
диагностики, источник и дату. После нажатия браузер открывает HTTPS-сайт партнёра;
как при обычном посещении сайта, партнёр может получить IP-адрес, User-Agent и
другие данные согласно собственной политике приватности.

Сотрудники партнёра видят в кабинете только обезличенные переходы к товарам своей
организации: товар, источник и дату. Им не доступны email клиента, внутренние ID
пользователя и диагностики, симптомы, ответы или фотографии.

Для атрибуции продажи партнёр может добавить к переходу собственный номер заказа и
сумму. В этом поле запрещены имя, email, телефон, адрес и иные данные клиента.
Администратор видит коммерческую ссылку и принимает либо отклоняет конверсию;
пользовательские диагностические данные партнёру при этом не раскрываются.

## Оплата подписки

При подключённом Stripe пользователь переходит на размещённую Stripe страницу
Checkout. AI Garden не получает и не хранит номер карты, CVC или полный платёжный
инструмент. В собственной базе сохраняются только внутренний пользователь,
тариф, статус и сроки подписки, Stripe Customer/Subscription ID и уникальные ID
обработанных webhook-событий. Управление способом оплаты выполняется через Stripe
Customer Portal. Применяется также политика конфиденциальности Stripe.

## Telegram

После добровольной привязки сохраняются Telegram chat ID, username при его наличии,
язык и технические ID обработанных обновлений. Для повторной доставки ответа
временно хранится текст ответа бота. Команды `/plants` и `/today` формируют краткий
ответ из названий растений, задач и времени; фотографии, симптомы, результаты
диагностики, email и платёжные сведения в Telegram не отправляются. Пользователь
может отключить связь в приложении или командой `/unlink`.

## Права пользователя и сроки хранения

Пользователь может выгрузить данные через `GET /api/v1/users/me/export` и удалить
аккаунт, связанные записи и фотографии через `DELETE /api/v1/users/me`. Завершённые
jobs, уведомления, технические AI-журналы, integration/billing events, истёкшие
сессии и одноразовые токены автоматически очищаются ежедневной maintenance-задачей;
сроки задаются переменными `*_RETENTION_DAYS`. Конкретные production-сроки и
юридические основания должны быть утверждены оператором данных до запуска.
