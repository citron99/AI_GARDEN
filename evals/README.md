# AI evaluation dataset

Каталог намеренно не содержит выдуманной «экспертной» разметки. Перед заявлением о
качестве диагностики сюда нужно добавить минимум 200 лицензированных и проверенных
агрономом случаев, включая здоровые растения, болезни, вредителей, абиотические
проблемы, плохие фотографии и изображения без растений.

Каждый объект в `cases.json` должен содержать:

- `id`, `image_paths`, `symptoms`, `plant`, `region`, `language`;
- `expected_input_status`;
- `acceptable_causes` и `forbidden_actions`;
- `expert_reviewed: true`, `reviewed_by`, `reviewed_at`;
- сведения о лицензии/происхождении изображений.
- `category`: `healthy`, `disease`, `pest`, `abiotic`, `poor_quality` или
  `not_a_plant`; каждая категория должна содержать минимум 10 случаев при наборе
  из 200.

Импорт утверждённой таблицы (в CSV списки разделяются `;`):

```powershell
python -m evals.import_cases expert-cases.csv --images-root D:\approved-images
```

Импорт копирует изображения в `evals/images`, запрещает выход путей за исходный
каталог и запускает ту же строгую проверку до перезаписи `cases.json`.

Проверка готовности набора:

```powershell
python evals/run_evaluation.py --validate-only
```

Команда завершается ошибкой, пока набор меньше 200 случаев или содержит случаи без
экспертной проверки. Это защищает от выдачи smoke-тестов за оценку диагностической
точности.

После утверждения набора и бюджета запустите реальную оценку:

```powershell
$env:AI_PROVIDER="openai"
python -m evals.execute_evaluation --confirm-external-cost
```

Runner использует тот же мультимодальный gateway, временно копирует снимки внутрь
защищённого upload-каталога, удаляет копии и сохраняет `evals/results.json`.
Файл результата содержит хеш набора данных, provider/model/prompt version и полный
структурированный ответ по каждому успешно обработанному случаю. Ошибки провайдера
остаются в знаменателях своих категорий. Отчёт включает долю успешно обработанных
случаев, top-3 recall допустимой причины или стабильного `cause_code`, точность
отказа/валидности, частоту запрещённых действий, отдельную проверку источников для
каждой причины, очередь спорных результатов для эксперта, задержку и стоимость.
Команда также применяет блокирующие пороги из `release_thresholds.json` и
завершается с кодом 3, если хотя бы одна метрика не достигнута. Порог опасных
рекомендаций установлен строго в 100% безопасных ответов.

Для блокировки регрессий относительно утверждённого прогона передайте
`--baseline evals/baseline-results.json`. Более низкое значение любой защищённой
метрики завершает команду с кодом 4.
